# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Python developers evaluating Crosswind because they want Cloudflare's TypeScript-only developer kits in Python. They need to see the packages and real code, pick a package, and start. People already using Crosswind are the second audience, and they use the docs as reference.

## Product Purpose

Crosswind is an unofficial set of typed, async Python SDKs and tools for Cloudflare Python Workers. Each package ports one TypeScript kit or official tool, so developers subclass Python classes and never write Pyodide or FFI calls.

## Positioning

Each SDK keeps the wire protocol of its official counterpart, so TypeScript clients such as the `useAgent` React hook connect to a Python Worker unchanged.

## Capabilities and Constraints

- Packages: `cf-agents`, `containers-py`, `crosswind-sandboxes`, `crosswind-workers` and the `wynd` CLI.
- The docs site is MkDocs Material, deployed on Cloudflare Pages, with API pages generated by mkdocstrings.
- Every package is alpha and pre-1.0. The docs must keep telling readers to pin exact versions.
- Python Workers run on Pyodide, so not every PyPI package imports.

## Brand Commitments

- The name is Crosswind and the puffin logo stays.
- Crosswind is independent and not affiliated with or endorsed by Cloudflare. The docs must say so.
- The user pinned the visual direction: dark, minimal, native tooling. See `DESIGN.md`.

## Evidence on Hand

- Mosslight Valley, a demo game whose server uses `cf-agents`.
- No customers, benchmarks or testimonials exist. Do not invent them.

## Product Principles

- Show code before claims.
- Keep Python types at every public boundary.
- State what is alpha or missing.
